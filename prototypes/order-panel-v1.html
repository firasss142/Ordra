    Ce que le panneau ajoute

    • 1
      Pastille SLAnouveau
      L'âge existe déjà (order-age.ts) mais il n'y a pas d'objectif : il faut un sla_minutes par marché dans settings.
    • 2
      Fiabilité clientdonnées existantes
      /api/customer-history renvoie déjà total_orders / delivered_count / returned_count — aujourd'hui seulement dans un popover au survol. Réduit ici à une ligne : carton = commandes, coche = livrées, flèche retour = retours. Les mots restent au survol.
      Verdict en un mot — Fiable / Moyen / À risque — la pastille porte le niveau. Le seuil reste à fixer (proposition : ≥ 85 % livrées = fiable, < 60 % ou ≥ 2 retours = à risque, et « — » sous 3 commandes, faute d'historique).

    Agent vs super admin

    • AccentVert file agent (--agent-primary) / violet console (--oms-accent)
    • En-têteSLA pour les deux ; « Modifier statut » admin seulement
    • AgentLecture seule / « Réassigner » pour l'admin
    • EncartAucun des deux — le panneau reste identité, destination, articles
    • PiedTrois issues d'appel / mêmes issues + annulation, fulfillment, restauration
    • ÉditionAgent : sa commande, hors statuts bloqués. Admin : toujours

    Décision à trancher

    Le pied de page éclate « Appel terminé » en trois issues explicites (Confirmer / Rappeler / Refuser). Aujourd'hui c'est un seul CTA qui ouvre PostCallActionSheet. Trois boutons = un clic de moins, mais « Refuser » demande toujours un motif, donc la feuille reste nécessaire pour ce chemin — et resolvePanelActions devra renvoyer plusieurs actions primaires au lieu d'une.
