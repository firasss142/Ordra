## Critical Failures (P0 — Fix Before Any Other Session)

> **[1.4 / 1.6 / 11.2] RTL direction not applied to html element**
> Expected: `html[dir="rtl"]` for any /ar/ route (Libya market)
> Actual: `html[dir="ltr"]` for all routes — root layout `src/app/layout.tsx` defaults locale to `"fr"` because Next.js App Router does not pass `locale` to the root segment params
> Impact: Entire Arabic/RTL market is visually broken — layout, text alignment, sidebar position all wrong
> Fix location: `src/app/layout.tsx` — remove dir logic here; set `lang` and `dir` in the `[locale]` layout at `src/app/[locale]/layout.tsx` on the outermost wrapper, or pass them down via a root layout that reads from the URL segment

> **[11.2 / 11.4] Arabic market shows French UI (i18n completely broken for Libya)**
> Expected: manager.ly and agent1.ly see Arabic text throughout
> Actual: All UI in French — same navigation labels, same button text, same table headers
> Impact: Libya market is completely unusable for Arabic-speaking users
> Fix location: Root cause likely in how `NextIntlClientProvider` receives locale — check `src/app/[locale]/layout.tsx` message passing. The `ar.json` file exists and has translations; issue is in rendering pipeline.

> **[7.7] Stock changes NOT atomic — risk of partial writes**
> Expected: Order status update + inventory_log insert + product stock update wrapped in a single DB transaction
> Actual: Three sequential `await supabase.from(...).update/insert()` calls in `src/lib/fulfillment-engine.ts` with no transaction wrapper — if step 2 or 3 fails, stock could be decremented but status not updated (or vice versa)
> Impact: Data integrity risk — stock counts can become incorrect on any mid-operation failure
> Fix location: `src/lib/fulfillment-engine.ts` — wrap all DB operations in a Supabase RPC function (Postgres transaction) or use `supabase.rpc()` to execute atomically
